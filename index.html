MIDI → .riffle

Converts a standard MIDI file into a RifflerFLOW-compatible .riffle file. Runs entirely in your browser — nothing is uploaded anywhere.

input
A known-good template is built in, so this is optional — only upload one if you want a different starting header. Either way, only its header donates fields; the note data and several specific header fields (see below) are always fully computed from your MIDI.
Use this if your MIDI came from a live-recorded MIDI-out stream rather than a true export — those often carry a placeholder tempo instead of the real one.
Bar breaks are placed by elapsed time (a 4/4 bar = 4 beats), read from the MIDI's time signature. Override it here if your MIDI doesn't specify one, or specifies the wrong one.

what's verified vs. still a placeholder
  • Pitch (riffle note = MIDI note − 12) — confirmed exactly against a 64-note reference file
  • Duration (fixed grid, quarter note = 1000 ticks, independent of tempo) — confirmed; kept as real per-note values rather than left untouched, since a separate tool's "duration doesn't matter" claim was tested here and directly contradicted by this project's own byte-exact ground truth
  • Tempo (header field = BPM × 100) — confirmed
  • Bar breaks placed by elapsed time against the real time signature, with explicit rests for silence — confirmed on a monophonic example
  • Header fields 7,11,12,13,14,16,42,43,48 zeroed and fields 5→7, 46→5 — adopted from a separate real-world test that watched RifflerFLOW itself re-save a converted file
  • Safety caps: 8 bars and 128 note-slots, whichever is hit first — the 8-bar limit came from a real crash in testing; the 128-slot figure is adopted from a separate confirmed-safe test
  • Chords (simultaneous notes) are unrolled into a fast sequential arpeggio, each keeping its own sustain length — a reasonable but unverified choice; our only confirmed example never had two notes at once
  • A claimed pitch ceiling of 64 (from that same separate test) was checked against this project's ground truth and found to be contradicted by a real file — not applied
  • Chord-name labels shown in the app — not reproduced, so they may not match your converted notes
  • A possible second "layer" some .riffle files carry (e.g. a chord-strum accompaniment alongside the melodic line) — not reproduced
